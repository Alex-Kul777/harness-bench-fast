# dedupe-fork-wave-tasks

## Why

Агрегация Medium-волн в `scripts/build_fork_pages.py` сегодня **суммирует**
`summary.passed` / `summary.total` каждого артефакта конфигурации. Когда по одной волне
существует несколько файлов (перезапуск / догоняющий прогон), их итоги складываются и
завышают волну.

Наблюдаемый дефект: конфиг **OpenClaw × DeepSeek-V4.1-Flash (thinking: off)** показывает
волну `long` как **8** при покрытии **68/90** вместо **66/90**. Причина — по этой
конфигурации в `results/` лежат два long-файла:

- `oc_medium_long_ds41flash_off_20261108.json` — 2 задачи (392, 393), **устаревший
  частичный** прогон;
- `oc_medium_long_ds41flash_off_20261109.json` — 6 задач (392, 393, 394, 395, 398, 403),
  **догоняющий** прогон.

2 + 6 = 8 → 8 + 20 (reflect) + 40 (feasibility) = **68**, тогда как medium/high имеют по
одному long-файлу и дают честные **66**. Число уникальных задач волны — 6 (догоняющий
прогон надмножеством перекрывает устаревший частичный).

## What Changes

- **Дедупликация волны по UNION номеров задач.** В `build_model()` (per config+wave)
  вместо суммирования `summary.total` / `summary.passed` строится карта
  `number -> passed(bool)` по per-task записям артефактов волны; номер парсится из поля
  `number` либо (fallback) из `task_(\d+)` в `task_id`. Артефакты волны обрабатываются в
  **возрастающем порядке имени файла** (имена заканчиваются `_YYYYMMDD`, поэтому
  лексикографический порядок = хронологический): более поздний артефакт **перекрывает**
  более ранний для того же номера.
- **Результат волны:** `total` = число различных номеров, `passed` = число `True`.
- **Fallback:** если ни один артефакт волны не даёт разбираемых номеров — сохраняется
  старое поведение (сумма `summary` totals) для этой волны (документируется в `design.md`).
- **Тестируемость:** `build_model()` принимает необязательный параметр каталогов
  результатов (по умолчанию `RESULT_DIRS`), не ломая существующих вызовов.
- **Регрессионный тест** `tests/test_fork_wave_task_union.py`: два перекрывающихся
  временных артефакта (частичный на 2 задачи + догоняющий на 6) для одной config+wave;
  волна обязана дать `total == 6` и ожидаемый `passed`.

## Impact

- Изменяется: `scripts/build_fork_pages.py` (`build_model()` — агрегация волн + опциональный
  параметр каталогов).
- Добавляется: `tests/test_fork_wave_task_union.py`.
- Регенерируются: `docs/fork-medium90-results.json`, `docs/fork-run-*.html`,
  `docs/fork-results.md` (значения волны `long` у off-конфига 8 → 6).

## Out of scope

- **Агрегация usage (seconds / steps / tokens / cost_rub)** — НЕ меняется в этом изменении;
  перекрывающиеся артефакты по-прежнему суммируются по usage. Вынесено отдельно.
- Логика измерения/`expected` (`WAVES[wave][2]`) и `wilson_interval` — НЕ меняются.
- Смысл метрик, upstream-строки, сами `results/*.json` — не трогаются.
