# dedupe-fork-wave-tasks — design

## Контекст

`scripts/build_fork_pages.py::build_model()` группирует артефакты по
`(harness, model, profile)` и по волнам, но свод волны — это накопительная сумма
`summary.passed` / `summary.total` по всем файлам конфигурации:

```python
suit = group["suites"][wave]
suit["passed"] += int(summary.get("passed") or 0)
suit["total"]  += int(summary.get("total") or 0)
```

Когда по волне есть перекрывающиеся файлы (перезапуск + догоняющий прогон), итоги
складываются и завышают покрытие. Пример — off-конфиг: long 8 вместо 6 (см. `proposal.md`).

## Решение

Per (config, wave) перейти от суммы к **UNION по номерам задач**:

1. Per-task записи читаются из `data.get("results") or data.get("tasks")` (список).
   **Оба источника обязательны:** OpenClaw-runner кладёт задачи в top-level `tasks`
   (напр. `oc_medium_long_ds41flash_off_*.json`), Pi-runner — в `results`.
2. Номер задачи: поле `number`, иначе regex `task_(\d+)` по `task_id`
   (зеркалит `build_fork_home._TASK_NUM_RE`).
3. Карта `number -> passed(bool)` на волну; артефакты обрабатываются в **возрастающем
   порядке имени файла**. Имена заканчиваются `_YYYYMMDD`, поэтому лексикографический
   порядок = хронологический; более поздний артефакт **перекрывает** более ранний для
   того же номера.
4. Итог волны: `total` = число различных номеров, `passed` = число `True`.

### Fallback

Если **ни один** артефакт волны не дал разбираемых номеров (карта пуста), сохраняется
**старое поведение** — сумма `summary.passed` / `summary.total` по артефактам этой волны.
Это защищает конфигурации/артефакты без per-task массива от обнуления волны.

### Тестируемость

`build_model()` получает необязательный параметр `result_dirs` (по умолчанию
`RESULT_DIRS`), прокидываемый в `collect_paths(result_dirs)`. Существующие вызовы
(`main`, генераторы) не меняются.

## Границы и риски

- **Usage-агрегация (seconds / steps / tokens / cost_rub) — OUT OF SCOPE**: остаётся
  суммированием по всем артефактам. Перекрывающиеся файлы по-прежнему складываются в
  usage. Вынесено в отдельное изменение.
- `wilson_interval` и `WAVES[wave][2]` (measurement `partial`/`complete`) — не меняются.
- Порядок обработки задаётся сортировкой по имени, а не порядком обхода каталогов, — так
  результат детерминирован независимо от `RESULT_DIRS`.
- Риск регрессии нулевых номеров закрыт fallback-веткой.

## Альтернативы

- Дедуп по `task_id` строке вместо номера — отвергнут: перекрывающиеся артефакты могут
  форматировать `task_id` по-разному; номер — канонический ключ волны.
- «Побеждает наибольший файл» / «последний по mtime» — отвергнуты: mtime нестабилен в
  архивах/CI; имя (`_YYYYMMDD`) — воспроизводимый хронологический ключ.
