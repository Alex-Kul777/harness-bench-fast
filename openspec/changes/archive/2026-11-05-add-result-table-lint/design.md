# add-result-table-lint — design

## Context

См. `proposal.md` — Why. Скрипт `scripts/build_fork_results.py` уже генерирует
авто-блок с каноническими колонками; статические таблицы в `FORK.md` и
`docs/fork-results.md` пишутся руками и могут расходиться со схемой.

## Goals / Non-Goals

- **Goals:** дешёвая, CI-friendly проверка присутствия канонических колонок в
  результатных таблицах.
- **Non-Goals:** полноценный Markdown-AST, проверка числовых значений, проверка
  служебных таблиц «Что | Где».

## Decisions

- **Флаг `--lint` в существующем скрипте**, а не отдельный инструмент: переиспользуем
  знание о путях к файлам и один вход для CI. Альтернатива (markdown-lint парсер)
  отклонена — лишняя зависимость.
- **Идентификация результатной таблицы:** таблица считается результатной, если её
  заголовок содержит и `Model`, и `Result`. Служебные таблицы («Что | Где») не подходят.
- **Проверка колонок:** обязательные — `Harness`, `Profile`, `Model`, `Result`, `%`,
  `Time`, `Steps`, `Tokens`; `Tokens` матчится по префиксу, чтобы принять `Tokens (cost)`.
- **Код возврата:** `0` — все таблицы корректны; ненулевой — иначе (аналогично `--check`).

## Risks / Trade-offs

- [Эвристика по заголовку пропустит нетипичную таблицу] → требуем одновременно
  `Model` и `Result`; при сомнении расширяем правило.
- [Разные формулировки заголовков RU/EN] → сверяем по латинским именам колонок.

## Migration Plan

Добавить `--lint`, вызвать из CI. Откат — убрать флаг и шаг CI; данные не меняются.
