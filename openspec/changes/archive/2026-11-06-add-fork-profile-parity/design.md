# add-fork-profile-parity — design

## Формат (паритет с upstream)
- **Model**: `"<model> (<reasoning>)"`. Источник — профиль прогона:
  `thinking: off` → `(thinking: off)`; `high`/`medium`/`low`/`minimal` → `(<level>)`;
  `MCP off`/`—` → без суффикса. Применяется только к НАШИМ строкам
  (upstream-модели уже содержат уровень).

- **Harness**: `"<harness> <version>"` при наличии записи в артефакте. Порядок ключей:
  `harness_version` → `openclaw_version` → `cli_version` → `runner_version`.

## Ограничение (документируем)
Артефакты наших прогонов (`results/*.json`, `runs/*.json`) полей версии харнеса **не
содержат** (есть только `task_set_version` — это версия НАБОРА задач, отдельная колонка
Version). Поэтому у наших строк версия пока не появится, в отличие от upstream-строк
(`pi-mono 0.73.1` и т.п.). Не подставляем «примерную» версию — на странице результатов
важна точность (иначе получилось бы «OpenClaw 2026.9.6 (2026-08-12)»).

## Стратегический фикс (follow-up)
Раннеры (`run_openclaw_bench.py`, pi/hermes-раннеры) должны записывать версию харнеса в
артефакт (`harness_version`). После этого колонка Harness заполнится автоматически —
плумбинг уже готов.
