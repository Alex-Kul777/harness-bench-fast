# add-fork-bilingual-en-ru — design

## Контекст

Форк уже собирается генераторами (`build_fork_home.py`, `build_fork_pages.py`,
`build_fork_results.py`) из JSON-данных, а `--check`-режимы следят за актуальностью. Любая
двуязычность должна встраиваться в эту схему и не ломать merge-guard'ы
(`<!-- FORK:BEGIN -->`, `FORK:RESULTS`) и линт канонических колонок.

## Решения

### 1. Дефолт — RU, EN — зеркало (`.en`)

Форк объявлен «Russian-first» (`openspec/config.yaml`). Поэтому RU-файлы остаются дефолтом
(`FORK.md`, `docs/fork.html`, `docs/fork-results.md`), а EN-версии публикуются зеркалами с
суффиксом `.en`. Upstream (`README.md`, upstream-строки) — английский и **не трогается**.

### 2. Статические зеркала, а не клиентский JS-переключатель

EN-страница генерируется тем же генератором с параметром локали; переключатель — обычная
ссылка RU⇄EN, сохраняющая якорь. Это даёт:

- сохранение требования «без JS страница читаема» (спека `result-reporting`);
- детерминизм и покрытие `--check` (оба файла проверяемы);
- корректный markdown в GitHub (`FORK.en.md`, `docs/fork-results.en.md`);
- отсутствие дрейфа клиентского каталога.

### 3. Каталог локалей в Python (`scripts/fork_i18n.py`)

Один словарь `CATALOG = {"ru": {...}, "en": {...}}` + helper `t(locale, key)` с fallback на
дефолтную локаль. Источник — единый для всех трёх генераторов. Отсутствующий перевод не
роняет сборку (fallback + тест симметрии ключей).

### 4. Канонические колонки — английские в обеих локалях

`--lint` требует колонки `Harness`/`Profile`/…/`Tokens (cost)` в `FORK.md` и
`docs/fork-results.md`. Локализуем только chrome, прозу, заметки, групповые подписи и
статусы (`partial`, `pilot (truncated)`, `upstream (subset)`). Данные и заголовки колонок —
как есть.

### 5. Паритет локалей как проверка

По образцу earlier-change `add-fork-profile-parity`: RU и EN обязаны иметь идентичный набор
строк данных. Проверка — в `--check`/тесте (сравнение нормализованных строк по каждому набору).

## Отвергнуто

- **Клиентский `data-i18n` + JS-toggle** — ломает no-JS-читаемость, усложняет `--check`/SEO.
- **Двуязычные подписи в одной ячейке** («Our runs / Наши прогоны») — визуальный шум и ломка
  9-колоночной схемы.
- **Перевод заголовков колонок/данных** — конфликт с `--lint` и upstream-совместимостью.
- **Отдельный сайт/ветка для EN** — расходится с публикацией `/docs` через GitHub Pages и с
  требованием «одна страница на URL-hash».
- **Авто-детект языка браузера** — нестабильно в статике, выносится за скоуп.

## Риски и митигации

- **Дублирование файлов (×2)** → генерация из одного источника + паритет-проверка + `--check`
  для обеих локалей.
- **Дрейф каталога** → fallback на RU + тест симметрии ключей.
- **Расхождение detail-страниц** → те же шаблоны, отличие только в каталоге подписей.
- **Merge upstream** → EN-зеркала — новые fork-only файлы, конфликтов с upstream не создают;
  RU-дефолт сохраняет текущие merge-guard'ы.

## Проверка (verify)

- `python3 scripts/build_fork_results.py --check` / `--lint` → 0 (RU и EN);
  `python3 scripts/build_fork_home.py --check` → 0; `python3 scripts/build_fork_pages.py --check` → 0.
- `npx -y @fission-ai/openspec@1.16.0 validate --all --strict` → 0.
- Паритет-тест: строки данных RU == EN по каждому набору.
- Live: `fork.html` и `fork.en.html` → 200; переключение локали сохраняет таб; без JS видно
  дефолтную (RU) страницу целиком.
