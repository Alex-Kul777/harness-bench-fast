# add-fork-publish-orchestrator — design

## Контекст

Публикация форк-слоя сегодня — ручная цепочка из трёх генераторов с дублированным
классификатором модели и ручным git/Pages-шагом. Между «прогон завершён» и «строка на
странице» связи нет: раннеры только пишут `results/*.json`. Решения зафиксированы в
`docs/adr/0005-fork-publish-orchestrator.md` (grilling-сессия: `ask-matt` →
`grill-with-docs`).

## Решения (ADR-0005)

- **Q1 — единый вход:** `scripts/publish_fork.py` (Python; генераторы — Python, нужен
  импорт для `collect_paths()`).
- **Q2 — единый источник метаданных:** `scripts/fork_metadata.py` (`HARNESS_PREFIXES`,
  `MODEL_TOKENS`, `THINKING_LEVEL_RE`, резолвер stem→(harness, model, level),
  `collect_paths()`); три генератора и оркестратор импортируют его.
- **Q3 — автозапуск (override владельца):** флаг раннера `--publish` по умолчанию ВКЛ.
- **Q4 — push по умолчанию (override владельца):** оркестратор коммитит и пушит по
  умолчанию; отменяет прежнее «не пушить, пока владелец не попросит».
- **Q5 — конкурентный гард** инкапсулирован в оркестраторе.
- **Q6 — процесс:** OpenSpec-change на ветке `fix/fork-run-steps`; `main` не трогаем.
- **Q7/Q11 — hard-fail:** нерезолвимый stem и неполный прогон → ненулевой код.
- **Q8 — механизм автозапуска:** флаг раннера, без watcher-демона.
- **Q9 — цель push и гейт:** push в fork `main`, fail-closed (только при зелёных
  `--check`/`--lint` на чистом архиве; иначе аборт, коммит остаётся на ветке).
- **Q10 — опт-ауты:** `--no-publish`, `--no-commit`, `--no-push`, `--dry-run`.

## Альтернативы

- Watcher-automation на `results/` — отвергнут: демон + гонки, избыточен при флаге в
  раннере.
- JSON-файл метаданных вместо модуля — отвергнут: резолвер и `collect_paths()` — код,
  их всё равно нужно исполнять.
- Push в ветку + PR — отвергнут владельцем (Q4/Q9): нужен живой `main` для Pages.

## Границы и риски

- Схема публикуемых страниц/колонок НЕ меняется (parity-тест на дедуп метаданных).
- Автозапуск + push по умолчанию повышают радиус поражения: частично компенсируется
  fail-closed `--check`/`--lint` и hard-fail на неполном прогоне.
- Живые прогоны соседних сессий из общего `../results/` изолируются гардом (Q5).
- Pages-workflow уже существует (`.github/workflows/pages.yml`), его не трогаем.
