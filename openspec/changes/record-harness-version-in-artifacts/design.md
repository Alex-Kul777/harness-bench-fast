# record-harness-version-in-artifacts — design

## Модель данных
Новое поле верхнего уровня артефакта: `harness_version: str` (напр. `pi-mono 0.73.1`,
`OpenClaw 2026.9.6`, `hermes 5307e932`). Пишется только когда известно; отсутствие поля —
честный случай «версия не записана» (страница покажет только имя харнеса).

## Как задаётся
1. Флаг `run-cli --harness-version "<ver>"`.
2. Fallback из env `HARNESS_BENCH_HARNESS_VERSION` (удобно для обёрток и CI).
Оба прокидываются через `set_results_json_harness_version(...)` (модульный глобал, как у
`command`), сбрасываются в `finally` — без утечки между прогонами.

## Почему не автодетект
Автоопределение (`<cli> --version`) — хрупко (разные форматы, лишний сабпроцесс, часть
харнесов не поддерживает). Оставляем явное значение; при необходимости авто-детект можно
добавить позже отдельным изменением.

## Совместимость с upstream
Правки аддитивные (новый символ + новое поле payload + новый CLI-флаг) — минимизируют
конфликты при мерже upstream.

## Follow-up (вне скоупа)
Обёртки `run_openclaw_bench.py` / pi / hermes должны передавать `--harness-version`.
После этого колонка Harness на `fork.html` заполнится сама.
